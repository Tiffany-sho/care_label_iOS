# carelabel

衣類のタグにある取扱い表示記号（JIS L 0001 / ISO 3758・41種）を選ぶと、洗い方を出す。

## 設計の前提

このアプリの存在意義は「記号を日本語に訳すこと」ではない。それは花王・ライオン・消費者庁が
無料で公開しており、既存アプリも複数ある。差別化は次の3点に置いている。

1. **「上限」と「可否」の語彙を徹底する。**
   「40」は *40℃で洗え* ではなく *40℃まで* の意味。既存のアプリ・記事はここを頻繁に誤訳する。
   出力の文言はすべて上限／可否で書き、「上限であって推奨温度ではない」と明示する。
2. **記号がない分類について推測しない。**
   表示がない＝「情報がない」であって「何をしてもよい」ではない。該当分類は `unknown` として
   その旨を出す。
3. **導出根拠を必ず出す。**
   どの指示がどの記号から来たかを、記号の図と JIS 記号番号つきで併記する。

## v0.1 に入っているもの

- 41記号のピッカー（7分類のタブ、1分類1記号）
- 記号の集合 → 洗い方（洗う／漂白／乾かす／アイロン／専門店）の規則エンジン
- 各指示の導出根拠の表示
- 記号の組み合わせとして不自然なものの警告（例: 家庭洗濯・ドライ・ウェットが全部禁止）
- 免責表示

## v0.1 に**入れていない**もの（意図的）

| 項目 | 理由 |
|---|---|
| 洗剤の推薦 | 記号から導けるのは洗剤の「属性」（中性／弱アルカリ性・蛍光増白剤の有無・漂白剤配合の可否）まで。商品名の推薦には別の商品DBが要り、価格と入手性で陳腐化する。属性を主・代表商品を従にする形で v0.2 に回す。 |
| 複数衣類の「一緒に洗える組み合わせ」判断 | 単品翻訳より価値が高いのはこちら（水温上限の最小値・洗い強度の最弱・漂白可否の AND を取る）。ただし v0.1 のスコープ外。 |
| タグ写真からの記号認識 | Web版のスコープ外。**iOSアプリ側で実装予定**で、実現可能性は合成データで実測済み → [IOS.md](IOS.md) / [tools/](tools/README.md)。要点: 基本形・下線・点は学習モデルなしで97〜100%、残る誤りはほぼ全部が記号内の文字（温度数字とP/F）。1記号100px以上が必須条件。認識結果は答えではなくピッカーのプリフィルとして扱う。 |
| クリーニング店・コインランドリー検索 | 別ドメイン（位置情報＋店舗DB）。汎用検索は地図アプリの劣化版になりやすい。 |

## 記号の描画について

41個の SVG を個別に持たず、`components/CareSymbol.tsx` で
「基本形（桶・三角・四角・円・アイロン）＋ 付加要素（数字・点・線・斜線・×）」の合成として描く。
JIS の記号体系自体が合成的なので、これが素直で、ライセンス上も安全（自作）。

**未検証**: 形状は公式記号の近似。特に次の2点は公開前に公式の記号一覧との照合が必要。
- 「日陰」を示す左上隅の斜線の向きと本数
- 「手洗い」の手の形

## 構成

```
lib/symbols.ts        41記号の定義（JISの意味 + 図形記述 + 規則エンジン用の構造化属性）
lib/glyphSvg.ts       記号の幾何（Web と生成ツールが共有する単一の情報源）
lib/plan.ts           記号の集合 → 洗い方 の規則エンジン
components/CareSymbol.tsx   ノード列 → SVG のレンダラ
components/Picker.tsx       ピッカーUI + 結果表示（client component）
app/page.tsx          ページ

tools/                合成データ生成と、認識精度の実測（→ tools/README.md）
ios/                  iOSアプリ側 Stage 2 のコア（Swift移植）＋テンプレート
IOS.md                測定にもとづく iOS 実装プラン
```
